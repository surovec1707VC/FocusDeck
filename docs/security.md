# Безопасность

Модель угроз, механизмы защиты и результаты аудита (октябрь 2026, версия 0.1.0).

## Модель угроз

FocusDeck — локальное приложение одного пользователя, работает с его правами.

**Что защищаем:**
- файлы и настройки Windows от случайных или навязанных разрушительных действий;
- секреты интеграций;
- данные приложения от порчи;
- пользователя от действий, на которые он не соглашался.

**Источники риска:**
- **Ввод из UI.** Фронтенд считается недоверенным: всё, что приходит в команды, проверяется в Rust.
- **Импортируемые файлы.** Конфигурация, данные, резервные копии и манифесты могут быть испорчены или подделаны.
- **Содержимое буфера обмена, имена файлов, ответы сети** — это данные, а не команды.
- **Обновления.** Пакет должен быть подписан нашим ключом.

**Вне модели:** вредоносная программа с правами пользователя — она и так может всё, что может FocusDeck.

## Слои защиты

| Слой | Где | Что делает |
|---|---|---|
| CSP | `tauri.conf.json` | `default-src 'self'`; сеть из WebView только к IPC; без внешних скриптов, стилей и шрифтов |
| Capabilities | `capabilities/*.json` | фронтенду доступны только окно (перетаскивание, свернуть, развернуть, закрыть) и `opener`; файловой системы, shell и HTTP у WebView нет |
| Модули | `productivity::require` | команда выключенного модуля возвращает `module_disabled` |
| Разрешения | `permissions/` | 22 разрешения; все рискованные по умолчанию **не выданы**; каждое изменение и каждый отказ пишутся в журнал |
| Safe Mode | `safety.rs` | в Safe Mode выполняются только действия из белого списка, любое изменение подтверждается |
| Подтверждения | `AppError::ConfirmationRequired` + `useGuarded` | необратимые и опасные действия выполняются только при `confirm: true` после диалога, где по умолчанию в фокусе «Отмена» |
| Action Log | `safety::finish` | у каждого чувствительного действия записываются кто, что, над чем, результат и данные для отмены |
| Пути | `fsguard.rs` | относительные пути не выходят за базовую папку; системные папки защищены |
| Процессы | `devtools::run_program` | программы запускаются со списком аргументов, без shell; у процесса скрытое окно, таймаут, «убийство» дерева процессов, вывод ограничен 1 МБ |
| Секреты | `integrations/secrets.rs` | Windows Credential Manager; в UI, базу, журналы и экспорт не попадают |
| Обновления | `updates.rs` | только подписанные пакеты (minisign); перед установкой база копируется |

## Аудит: результаты

### 1. Валидация пользовательского ввода
Все команды принимают типизированные структуры (serde): лишние поля и неверные типы отклоняются. Бизнес-правила проверяются отдельно: длины, диапазоны, перечисления, формат времени, хоткеи, URL. Настройки модулей и интеграций проверяются по схеме, неизвестные ключи отклоняются. Сообщения об ошибках возвращаются на русском в виде `{ kind, message }`; паник на пользовательских данных нет — это покрыто IPC-тестами.

**Исправлено:** имя процесса в автоматизациях раньше допускало `& | < > ^ %` — теперь только буквы, цифры и `._-+()` (`automation/types.rs::check_process`).

### 2. Path traversal
- Git diff нового файла читал `repo.join(rel)`. Проверка `valid_rel_path` уже запрещала `..` и абсолютные пути. Добавлена `fsguard::inside`, которая сверяет и канонический путь, поэтому выйти из репозитория через ссылку тоже нельзя.
- Импорт данных пишет только в таблицы из белого списка и только в существующие колонки. Имена колонок из файла сверяются с `PRAGMA table_info`, поэтому SQL-инъекция через имя колонки невозможна (покрыто тестом).
- Резервная копия перед восстановлением открывается только на чтение и проверяется `quick_check` и набором таблиц.

### 3. Command injection
- **Исправлено:** закрытие программы (автоматизации) собирало строку `taskkill /IM "<имя>"` и выполняло её через `cmd`. Теперь `taskkill` запускается со списком аргументов, без shell.
- Git, терминалы, редакторы и проекты запускаются через `Command` со списком аргументов, `GIT_TERMINAL_PROMPT=0`; аргумент, начинающийся с `-`, не принимается за путь.
- **Осознанные исключения.** Пользовательские команды (быстрые действия, «Выполнить команду» в автоматизациях, вкладки терминала) по своей природе выполняются оболочкой. Их защищает разрешение `system.run_commands`, подтверждение каждого запуска и Action Log. Текст команды задаёт только сам пользователь.

### 4. Ограничение доступа к файлам
**Добавлено:** `fsguard::check_user_folder` — FocusDeck не перемещает и не удаляет в Корзину файлы:
- в корнях дисков;
- в `%WINDIR%`, `Program Files`, `ProgramData`;
- в корне профиля пользователя;
- в собственной папке данных.

Применяется в Desktop Organizer (целевая папка) и в действии «Удалить в Корзину». Покрыто тестом с подменённым планом перемещения.

Другие ограничения:
- Desktop Organizer берёт файлы только прямо с рабочего стола и никогда не удаляет — только перемещает, с откатом.
- Файлы безвозвратно не удаляются нигде: «удаление» — это Корзина.
- Интеграция «Локальные файлы» работает только с одной папкой, выбранной пользователем.

### 5. Хранение секретов
- Токены интеграций хранятся в Credential Manager (`FocusDeck/integration/<id>`); UI видит только флаг `has_secret`.
- Переменные окружения API Tester хранятся в базе открытым текстом. Это задокументировано в описании модуля: не храните там боевые секреты.
- В экспорт данных не входят ни Credential Manager, ни переменные API Tester.
- Ключ подписи обновлений хранится только у того, кто собирает релиз (переменная окружения CI), а не в репозитории — см. [release.md](release.md).

### 6. Журналирование опасных действий
В журнал пишутся:
- **Action Log** — действия Windows Integration, Git, терминала, проектов, API Tester, органайзера, быстрых действий, автоматизаций;
- **журнал разрешений** — выдача, отзыв и отказы;
- **журналы модулей и интеграций**;
- **журнал запусков автоматизаций** (до 500 на автоматизацию);
- **файловый лог** `tracing`: импорт и экспорт, резервные копии, восстановление, обновления, сбои.

### 7. Подтверждение необратимых действий
Подтверждения требуют:
- закрытие окон и программ;
- команды;
- Корзина;
- push и pull;
- смена схемы питания;
- закрытие рабочего стола;
- восстановление из копии;
- импорт данных;
- установка обновления и откат;
- удаление секрета интеграции;
- включение облачной интеграции;
- отключение критического модуля;
- удаление записей (заметки, задачи, макеты, правила).

## Известные ограничения
- Быстрые действия и команды автоматизаций выполняются через `cmd`. Это функция, а не уязвимость, но с выданным `system.run_commands` FocusDeck может выполнить всё, что вы туда впишете.
- Переменные окружения API Tester не шифруются.
- Приложение и установщик пока не подписаны сертификатом разработчика — SmartScreen будет предупреждать. См. [release.md](release.md).
- `opener` позволяет фронтенду открыть ссылку http(s) в браузере и показать файл в Проводнике. Других действий с файлами у фронтенда нет.

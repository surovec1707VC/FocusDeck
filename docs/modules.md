# Модули

Каждая функция FocusDeck — модуль реестра (`src-tauri/src/modules/catalog.rs`). Всего модулей: **43**, из них **39** можно выключить в Центре управления.

Когда модуль выключен:
- его команды отвечают ошибкой `module_disabled`;
- страница, пункт меню и виджеты скрываются;
- фоновая задача останавливается;
- данные сохраняются.

Включение возвращает всё как было.

Разрешения из колонки «Разрешения» модуль использует для своих действий. Все они, кроме уведомлений и глобальных горячих клавиш, по умолчанию не выданы. Подробнее — [security.md](security.md).

## Критические модули

Отключаются только после явного подтверждения. Центр управления доступен всегда, поэтому модуль легко вернуть.

| id | Название | Категория | По умолчанию | Разрешения | Что делает |
|---|---|---|---|---|---|
| `module_registry` | Реестр модулей | Инструменты разработчика | вкл. | — | Включение, отключение и настройка модулей. |
| `settings` | Настройки | Оформление | вкл. | — | Тема, окно, автозапуск и горячие клавиши приложения. |
| `database` | База данных | Производительность | вкл. | — | Обслуживание локальной базы SQLite, экспорт и импорт конфигурации. |
| `security` | Безопасность | Приватность и безопасность | вкл. | — | Разрешения функций и журнал их изменений. |

## Свойства модуля

| Поле | Значение |
|---|---|
| `enabled_by_default` | состояние при первом запуске |
| `critical` | для отключения нужно подтверждение |
| `requires_restart` | изменение вступит в силу после перезапуска (`pending_restart`) |
| `permissions` | разрешения, без которых модуль работает частично (статус `degraded`) |
| `settings_schema` | схема настроек: `type`, `title`, `default`, `minimum`, `maximum`, `enum`; неизвестные ключи отклоняются |

Статус модуля — `ok`, `degraded`, `error` или `disabled`. Его вычисляет `modules/health.rs`: проверяет, работает ли фоновая задача, выданы ли разрешения и цела ли база.

## Как добавить модуль
1. Константа и `ModuleDef` в `catalog.rs`. Новые модули с сетью, файлами или процессами по умолчанию **выключены**.
2. Команды модуля начинаются с `productivity::require(state, MODULE_ID)`.
3. Если нужна фоновая задача — добавьте её в `background.rs` (`spawn_for` и `OWNERS`).
4. Если нужна проверка статуса — добавьте ветку в `modules/health.rs`.
5. На фронтенде — маршрут в `App.tsx` внутри `<ModuleGate id>` и пункт меню с `module` в `Sidebar.tsx`.
6. Опишите модуль в документации и добавьте тесты.
